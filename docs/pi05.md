# LeRobot π₀.₅

The `pi05` plugin runs supervised training, chunked inference and action-expert reinforcement learning. The bundled policy includes the flow-matching objective, policy-specific processors and native PiGemma action expert. The installer supplies the matching LeRobot runtime for dataset loading and checkpoint processing. [Bundled policy](../src/pressb/model_sources/pi05/) · [Third-party notices](../THIRD_PARTY.md)

## Install the model environment

Use Python 3.10 or 3.11 with a PyTorch build for your device. From the repository root, install the pinned LeRobot runtime into the active environment and provision the base model and tokenizer. Choose a fresh tokenizer destination.

```bash
python scripts/install_pi05.py
hf download lerobot/pi05_base --local-dir .cache/pi05/base
python scripts/prepare_pi05_tokenizer.py --destination .cache/pi05/tokenizer
```

Set `policy.pretrained_path` and `tokenizer_path` in the training YAML to these directories. To use an existing local tokenizer, point `tokenizer_path` to its Hugging Face-compatible directory. For an Ascend host use the NPU environment instructions. [Ascend setup](ascend_pi05.md)

## Train on demonstrations

Copy the Cube Stack training YAML and set `dataset.root`, the two model paths, `policy.device` and a fresh `output_dir`. The example expects a LeRobot v3 dataset with `up` and `wrist` RGB streams. Its six joint-angle channels use degrees and its gripper channel uses full width in centimetres. The `pressb` mapping converts dataset units to the radians and metres used by the simulator. Adjust this mapping when training on another robot. [Training template](../configs/model_training/pi05_cube_stack.yaml)

```bash
python scripts/train_model.py --model pi05 --config /path/to/training.yaml -- --prepare-only
python scripts/train_model.py --model pi05 --config /path/to/training.yaml
```

The preparation command checks the episode split, dataset interface and normalization. Training splits by episode and applies image augmentation only to the training frames. Set `policy.chunk_size`, `policy.n_action_steps` and any `pressb.action.horizon` to the desired action window. The reader derives action timestamps from the chunk size.

For distributed training, launch one process per device. The effective batch size is the per-device `batch_size` multiplied by world size and `gradient_accumulation_steps`. The `steps` setting counts optimizer updates. Set `drop_last: true` when every update requires a full batch.

```bash
torchrun --standalone --nproc-per-node=2 scripts/train_model.py \
  --model pi05 --config /path/to/training.yaml
```

Rank zero performs validation and exports native LeRobot checkpoints, including the saved preprocessing and normalization processors, tokenizer and `pressb_pi05.json` action metadata. For inference, select `<output_dir>/checkpoints/last/pretrained_model` or the corresponding `best/pretrained_model`. These exports contain model parameters and processors. Continuing optimizer state requires a separate training checkpoint mechanism.

## Evaluate in simulation

Copy the Cube Stack experiment JSON. Set `model.config.checkpoint` to the exported `pretrained_model` directory, set the devices for inference and simulation, and check the camera names, units, control rate and execution horizon against the checkpoint. For a native LeRobot checkpoint without `pressb_pi05.json`, set `model.config.io` to declare the observation and action mapping. [Evaluation template](../configs/experiments/cube_stack_pi05_eval.json)

Validate the configuration, then run simulation, inference and evaluation in separate terminals. Run simulation in the Isaac environment and inference in the π₀.₅ environment. Each command uses the same experiment file.

```bash
python scripts/run_experiment.py validate --config /path/to/evaluation.json
python scripts/run_experiment.py simulation --config /path/to/evaluation.json
python scripts/run_experiment.py inference --config /path/to/evaluation.json
python scripts/run_experiment.py eval --config /path/to/evaluation.json \
  --episodes 20 --seed 43 --output outputs/pi05_eval
```

## Use π₀.₅ with online RL

For DSRL, `encode` computes the multimodal PaliGemma prefix. The RL feature is a masked mean over valid prefix tokens. The cached context carries the attention mask and per-layer keys and values. `decode` accepts external initial noise of shape `[chunk_size, max_action_dim]` and reuses the prefix while integrating the action expert. Set the model's `vision_attention` to `eager` (default) or `sdpa` for a compatible build. The learner's `noise_steps` determines the temporal resolution of the learned noise and affects checkpoint compatibility.

With DPPO, the `full` action-expert scope updates the Gemma action transformer, timestep MLPs and action projections. The frozen encoder supplies the prefix. RL training adds Gaussian noise at each denoising transition, and PPO scores the sampled chain. The saved processor converts the final latent to robot actions. If inference and all learner ranks share a filesystem, set `shared_prefix_dir` to a run-specific absolute directory to exchange prefix tensors. Otherwise, inference returns them in the response. [DPPO launch and checkpoint guide](dppo.md)
